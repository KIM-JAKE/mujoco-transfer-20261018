# 선택적 핀 끝면 원·축 직접 측정

기본 핀 검출기는 기존 `cad_icp`입니다. 이번 선택 기능은 Isaac 308에서 사용한 **RGB-D 끝면 plane + 실제 원주 측정**을 현장 카메라 입력 경로에 연결합니다. 현장 핀 정렬의 정밀도를 검증한 결과는 아니며, 실제 캡이 가려져 있으면 측정 실패로 중단합니다.

## 켜기

실제 사용하는 카메라 설정 JSON(`random-camera.json` 또는 역할별 설정)에 다음을 지정합니다.

```json
"pin_pose_backend": "measured_cap_circle"
```

카메라 역할별 파일을 쓰면 `pin_holder`, 핀을 든 `held_right`/`held_left`, `fixture` 중 실제 사용할 파일에 적용합니다. 같은 물리 카메라의 외부 보정은 역할에 따라 바꾸지 않습니다. 실제 고정 카메라에 끝면이 안 보이면, 검사된 로봇 관측 자세나 다른 실제 보정된 카메라가 필요합니다. 이 검출기는 카메라를 가상으로 이동하지 않습니다.

[핀 정밀 피드백](PIN_PRECISION.md)을 함께 켤 수 있습니다. 기존 영상/SDK/하중/경로/정지 검사는 그대로 적용됩니다. RGB-D 검출기 선택 자체가 이동 허가는 아닙니다. 값을 생략하거나 `cad_icp`로 지정하면 기본 검출기를 사용합니다.

## 입력과 측정

실제 등록된 RGB와 SDK의 organized XYZ/depth, 카메라 내부/외부 보정, 이전 **이미지**에서 얻은 핀 포즈와 현재 SDK TCP를 사용합니다. 핀 홀더/지그의 실측 목표는 탐색 ROI로만 사용합니다. 현재 중심·축은 새 픽셀에서 다시 구합니다.

1. 이전 영상과 SDK로 좁힌 ROI에서 회색 금속 픽셀과 유효 깊이를 고릅니다.
2. 실제 이웃 깊이 픽셀의 법선으로 핀 끝면 plane을 찾습니다.
3. 관측된 원주를 알려진 핀 끝 반경(2.5mm 또는 5.25mm)과 맞춥니다.
4. 240도 이상 원호, 12개 이상 원주 inlier, 전체 edge 중 75% 이상 지지, 반경 차이 ≤150µm, 원주 RMS ≤60µm와 끝면 RMS ≤60µm를 확인합니다.
5. 실제 측정된 끝면 중심에서 CAD의 17.75mm를 이동해 대칭축 중점을 구합니다. 기존 실행기에는 canonical CAD body 좌표로 돌려줍니다. 원형 물체의 관측 불가능한 축방향 yaw는 이전 이미지/홀더 보정의 값을 유지합니다.

이 임계값은 이상적인 시뮬 깊이에서 사용한 값입니다. 작은 fit residual은 실제 깊이·카메라 보정까지 75µm 정확하다는 뜻이 아닙니다. 반사·포화·깊이 구멍·원주 가림·잘못된 반경·부족한 plane이면 거부합니다. 이 모드가 실패할 때 이전 XY를 정답으로 복사하거나 ICP로 조용히 되돌아가지 않습니다. 오류가 나면 기존 팔 정지/완료된 파지 명령 보존 경로로 나갑니다.

## 확인한 범위

포함된 Isaac 308 **원본 RGB-D 네 프레임**을 공개 `detect_packet` 경로로 다시 처리했습니다. 이전 RGB-D 포즈와 기록된 시뮬 로봇 TCP로만 ROI를 전파했습니다. 네 프레임 모두 원본 시뮬 검출 결과의 대칭축 중심과 일치했고, 축 차이는 약 `1.5e-8rad` 이내였습니다. 초기 공개 검출기 실행은 CPU 0.185–0.302초/프레임이었고, 후속 재생에서는 약 0.19–0.35초였습니다. 촬영·SDK·이동 시간을 포함한 공정 시간은 아닙니다.

동일 프레임·같은 이미지 기반 ROI에서 기존 ICP는 두 프레임에서 fit을 거부했고, 나머지 두 fit은 원본 end-circle 측정과 중심이 약 2.1–2.7mm 달랐습니다. 이는 두 영상 추정기의 비교이며 actor 위치로 실제 오차를 측정한 결과가 아닙니다.

원본 시뮬은 서로 다른 가상 시점에서 보이는 끝면을 선택했습니다. 여러 실제 고정 카메라나 실제 로봇 관측 자세에서 같은 시야가 확보되는지, RealSense 금속 깊이에서 이 임계값을 만족하는지, 실제 파지·조립이 성공하는지는 미검증입니다. 기존 바구니 접근의 UNKNOWN 차단 문제를 해결한 기능도 아닙니다.

장비 없이 포함된 원본 영상을 공개 검출기로 다시 처리하려면:

```bash
PYTHONPATH=src python tools/replay_pin_cap_component.py
# 같은 영상에서 기존 ICP와 비교할 때만:
PYTHONPATH=src python tools/replay_pin_cap_component.py --compare-icp
```

입력은 모두 패키지 안에 있습니다. SDK/카메라/로봇에 접속하지 않으며 live freshness나 하드웨어 성공 증빙을 만들지 않습니다. [결과](../reports/pin-cap-public-detector-replay.json)와 [통합 상태](../reports/pin-cap-integration-status.json)를 확인합니다.
