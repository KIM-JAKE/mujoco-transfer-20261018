# 저장된 RGB-D와 현재 실행기 연결 결과

이 검사는 실제 저장된 **시뮬 카메라 픽셀**을 사용합니다. 실제 SDK·Hand·로봇·RealSense에 접속하지 않았습니다. 검사에서 사용한 SDK 모양의 상태/설치/정지 기록은 명시적 OFFLINE mock이며, 현장 승인 파일로 제공하지 않습니다.

## 이번에 고친 실행 문제

4mm 바구니 격자는 205,632 voxel이라 기존 200,000 기본 예산에서 중단됐습니다. 실행기와 카메라 템플릿에 명시적 기본 1,000,000을 적용했습니다. 격자·깊이 여유·UNKNOWN 판정은 변경하지 않았습니다.

선택 표면 검색은 후보 픽셀에 대해서만 KD 검색을 합니다. 같은 원본 영상에서 states/selected/unselected_hits/sources와 전체 직렬화 기록이 바이트 단위로 동일했습니다. 해당 격자 작성은 1.771→0.562초였습니다. [결과](../reports/recorded-occupancy-patch-regression.json)는 이 구성 요소의 시간이며 전체 공정/실기 시간은 아닙니다.

[5mrad 시운전](LOW_SPEED_COMMISSIONING.md)은 기본 20mrad 설정과 별도입니다. 실제 두 팔의 first-stop/telemetry·설정·바이너리·보정 해시가 맞아야 ready 프로파일을 만듭니다. 실제 read-only SDK 모델의 선택적 IK 초기값은 현재 측정된 q_d에서 시작하는 경로의 **해 탐색**에만 쓰이며 로봇에 초기 자세로 보내지 않습니다.

## 현재 접근은 아직 차단됨

v280 장면을 같은 저장된 시점 7.015576초의 CAD로 두 번 촬영했습니다. 하나는 바구니 수직 위, 하나는 글로벌 뷰입니다. 카메라 렌더러만 장면 스냅샷을 입력받고, 검출·경로 검사에는 RGB-D/카메라 보정과 로봇 관절 모델을 제공합니다. 초기 링 위치를 제어기에 입력하지 않습니다. 두 **가상 카메라**의 시험으로 실제 RealSense 한 대의 시야를 검증한 것이 아닙니다.

오버헤드 픽셀 검출 → 큰 링 선택 → occupied-wins 점유 융합 → 8개 파지 자세×3개 IK 초기값 → 현재 모델의 전체 로봇/반대팔/Hand/UNKNOWN 끝 자세 검사 순서로 연결했습니다. 24개 중 21개 IK가 풀렸으나 통과한 끝 자세는 0개입니다. [캠페인 결과](../reports/recorded-two-view-alternate-branches.json).

두 뷰는 실제 유효 ray가 증명한 UNKNOWN 4,573개를 FREE로 바꿨습니다. 원래 점유 셀은 모두 유지했습니다. 처음 막힌 왼쪽 바구니 립 인근 슬랩은 150개 모두 실제 UNKNOWN이며, 합쳐진 상자가 FREE 구멍을 채운 오류가 아닙니다. 개별 셀 최소 거리 33.137mm는 검사에 필요한 반경+여유 35.616mm보다 작습니다. [개별 셀 결과](../reports/recorded-two-view-exact-cell-blocker.json).

따라서 이 기록은 **접근·lease 발급·Hand 폐쇄·파지·전체 삽입을 완료한 결과가 아닙니다.** 추가 카메라를 선언했다고 장애물이 사라지는 것으로 처리하지 않았습니다. 현장 형상/카메라 보정과 시운전 결과에 따라 실제 통과 여부를 확인해야 합니다.

## 휴대 가능한 오프라인 재생

패키지 루트의 설치된 Python 환경에서:

```bash
PYTHONPATH=src python tools/replay_two_view_component.py
```

포함된 두 NPZ 영상만으로 융합과 원래 occupied 보존을 다시 검사합니다. SDK/로봇에 접속하지 않습니다. 원래 노출시각을 최신 실제 촬영으로 위장하지 않고 고정된 OFFLINE 비교 clock을 사용합니다. 실행은 결과를 출력하며 봉인 패키지 파일을 수정하지 않습니다.

`tools/render_global_v280.py`는 원본 Isaac archive와 컨테이너가 있는 개발 서버용 **영상 생성 출처 도구**입니다. 현장 패키지에서 독립 실행하는 도구가 아닙니다. 반면 위 재생 도구의 입력은 모두 패키지 안에 포함됩니다.

현재 live scene lease는 원래 단일 초기 카메라 출처에만 연결돼 있습니다. 이번 다중 뷰 융합은 구성 요소 시험이며 live 다중 뷰 lease 연동을 추가하지 않았습니다. 기존 기본 20mrad·실기 10% 속도·외력/heartbeat/실제 SDK 상태·파지 보존과 실패 처리 규칙은 유지합니다.
