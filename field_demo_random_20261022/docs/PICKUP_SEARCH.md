# 같은 크기 링의 후보 탐색

`random-cycle`과 `random-pick`은 RGB-D에서 접근 가능으로 판정된 **필요한 크기의 링**을 대상으로 파지 자세와 실제 SDK 모델의 IK 초기값을 검사합니다. 한 후보가 막혔다고 바로 집거나 충돌 검사를 생략하지 않습니다.

이번 수정은 탐색 순서입니다. 첫 초기값으로 여러 링·파지 자세를 먼저 확인한 뒤 다음 초기값을 시도합니다. 이전 순서는 첫 링의 초기값을 모두 소진한 다음 다음 링으로 넘어갔습니다. 예를 들어 링5개, 초기값4개, 계획 예산16회라면 앞의4개 링에서 예산을 모두 쓰고 다섯 번째 노출된 링을 확인하지 못할 수 있었습니다. 수정 후 같은 조건에서 다섯 번째 후보는5번째 계획에 검사됩니다.

- `pickup_search_max_plans`: 전체 읽기 전용 계획 횟수의 상한입니다. 기본16, 허용1–40이며5mrad 레시피는24입니다. 이번 수정으로 늘리지 않았습니다.
- `pickup_ik_seed_offsets_rad`: 실제 측정한 `q_d`에 더하는 초기값 후보1–4개입니다. 초기값은 명령할 관절 자세가 아니며, 실행은 다시 측정한 현재 상태에서 시작합니다.
- `pickup_search_max_captures`: 원래 촬영 횟수 상한을 유지합니다. 원래 영상 시각과 신선도 검사를 유지하며, 새 capture ID만 붙여 이미 실패한 동일 자세를 반복하지 않습니다.

일부 초기값만 실패한 후보는 나머지 초기값을 검사할 수 있습니다. 모든 초기값이 실패한 실제 목표만 실패 목록에 남깁니다. 계획 중 SDK/카메라 오류나 실제 이동 후 실패에 대한 재시도 범위를 넓히지 않았습니다. 이 함수는 이동이나 Hand 명령을 보내지 않습니다.

잔여 UNKNOWN, 바구니 벽, 설치한 부품, 전체 팔/손, 다른 팔, 하중·정지·추종·속도 검사는 그대로입니다. 모든 후보가 막히면 그대로 중단합니다. 분기 순서를 고친 것이며, 기존 기록에서 막힌 전체 접근/파지가 통과했다는 뜻은 아닙니다.

`reports/visible-target-search-regression.json`은 가짜 RGB-D/SDK/계획기를 명시한 경계 검사입니다. 실제 FR3·RealSense 파지 또는 공정 완료 결과가 아닙니다. 현장에서는 실제 보이는 링과 원래 `pickup_search_max_plans` 예산, 거부 이유를 확인하세요.
