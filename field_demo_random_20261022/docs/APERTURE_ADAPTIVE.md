# 실제 Hand 폭에 맞춘 동작과 제한된 후보 재선택

이 작업본은 기본 설치 절차를 바꾸지 않습니다. 먼저 [MODEL_STARTER.md](MODEL_STARTER.md)를 따라 현재 SDK 상태와 실제 설치 기록에서 새 설정을 작성하세요. 이전 실행 파일을 복사하지 말고 다시 빌드해야 합니다. 새 `m80_read_state`가 실제 SDK `robot_time_s`를 출력하며, 이전 바이너리는 정지 상태 Hand 감시에 필요한 시계를 제공하지 않습니다.

## Hand 모양과 실제 개방 폭

`model-preset author`가 `native_hand_aperture_geometry`를 넣습니다. 팔 이동을 계획할 때 양손의 **현재 SDK 폭**으로 원본 손가락 CAD를 배치합니다. 현재 폭 ±0.5mm 범위를 감싸며, 팔 이동 직전과 기존 heartbeat/readiness 루프에서 양손의 실제 폭·SDK 시각을 다시 확인합니다. 표본이 200ms를 넘거나 시계가 퇴행/정지하거나 확인한 폭 범위를 벗어나면 중단합니다. 목표 폭을 현재 폭으로 간주하지 않습니다.

따라서 작은 링을 64mm로 잡고 있을 때 계속 80mm 전체 개방 모양으로 삽입을 판정하지 않습니다. 원본 Hand 형상을 줄인 것이 아니라 실제 SDK가 확인한 관절 폭에서 같은 CAD를 변환한 것입니다. 이 조건부 감시는 미관측 폭 변화나 실제 정지 거리를 인증하지 않습니다.

실제 개방/파지 명령 전에는 양팔을 멈춘 실제 SDK FK와 새 RGB-D로 **현재 폭→명령 폭 전체 구간**을 검사합니다. 파지 허용 epsilon까지 포함하며, 벽·손바닥·팔·반대 팔·운반 물체 검사는 유지합니다. 의도한 손가락 접촉만 기존 명시적 contact 기술의 허용 범위를 따릅니다. 좁은 지그에서 80mm까지 실제로 열 수 없다면 그 명령을 거부합니다. 현장에서 실제 부품을 놓기에 충분한 release 폭을 설정해야 합니다.

Hand 명령 중에는 실제 양팔 SDK의 외력/모멘트와 정지 자세를 별도 읽기로 감시합니다. 기존 5N/1Nm 기준, 200ms 유효기간, 증가하는 실제 SDK 시각을 사용합니다. 독립적인 pad 센서를 만들어내지 않습니다. 이 모니터가 실패한 부분 파지를 물체 유지로 간주하지 않습니다.

처음 빈 손을 여는 동작은 **pickup 경로를 계획하기 전에** 정지 자세에서 검사하고 수행합니다. 닫힌 손 모양으로 계획한 뒤 80mm로 열어서 그대로 이동하는 경로 불일치를 방지합니다.

## 섞인 링에서 다른 후보 선택

기존에도 같은 크기의 여러 링과 여러 파지 자세를 시도했습니다. 현재는 한 링의 모든 yaw를 먼저 소모하지 않고, 같은 파지 계열에서 **다른 보이는 동일 크기 링**을 먼저 시도합니다.

- 검색 1회당 기본 한도: 계획 16회, 촬영 2회. `pickup_search_max_plans`는 1–40, `pickup_search_max_captures`는 1–4 안에서 설정할 수 있습니다.
- 영상이 오래되면 새 실제 영상을 받습니다. 새 capture ID가 생겼다는 이유로 똑같이 실패한 물리적 TCP/접근 목표를 다시 시도하지 않습니다.
- 읽기 전용 native IK의 정확한 “해당 목표 해 없음”과 “60초 경로 상한 초과”만 후보 실패로 넘깁니다. SDK 통신·상태 오류를 IK 실패로 숨기지 않습니다.
- 팔을 움직이기 **전** 새 영상에서 목표/장애물이 달라진 경우에만 한 번 다른 후보를 고릅니다. 팔 실행 상태가 불확실하거나 실제 파지 후 실패한 경우에는 자동 재시도하지 않습니다. 기존 정지/파지 보존/확인된 반환 절차를 따릅니다.

여전히 현재 픽셀에서 크기·자세를 구합니다. 시뮬 actor ID, 초기 부품 좌표, 특정 링의 고정 배치를 사용하지 않습니다. 보이는 같은 크기 링이 모두 가려졌거나 안전한 경로가 없으면 성공으로 처리하지 않습니다.

## 검사 범위

원본 official Hand CAD에 대해 64mm에서는 통과하고 80mm에서는 충돌하는 고정판 예제를 검사했습니다. 같은 예제에서 64→80mm **전체 개방 sweep은 충돌**합니다. 전체 손가락 원본 정점이 모든 중간 폭의 보수적 모양에 포함되는지도 검사합니다. 이 결과와 가짜 SDK/장치 경계 테스트는 실제 로봇 파지·힘·조립 성공을 증명하지 않습니다.

현재 남아 있는 실제 blocker: 바구니 RGB-D에 보이는 Hand 자체 표면은 아직 잔여 점유에서 별도 body로 구분하지 않습니다. 따라서 in-bin 정지 파지 sweep이 자기 표면을 장애물로 보고 거부할 수 있습니다. 이 작업본은 해당 점유나 UNKNOWN을 지워 통과시키지 않습니다. 실제 파지 전 단계 전체가 현장에서 통과했다고 표시하지 않습니다.
