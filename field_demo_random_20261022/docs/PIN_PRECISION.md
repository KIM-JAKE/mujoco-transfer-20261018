# 선택적 핀 삽입 전 RGB-D 피드백

핀을 든 뒤 지그 아래에서 새 이미지와 실제 SDK TCP를 반복 관측해 중심·축을 맞추는 **선택 기능**입니다. 기존 설정은 그대로이며 새 템플릿에서도 비활성입니다. 실제 바구니 접근이 막혀 있는 현재 기록을 해결한 기능이나 실기 성공 결과가 아닙니다.

실제 측정한 핀 지그 목표·카메라·파지·하중·기존 `preinsert`/`insert` 통로와 native 실행기/STOP 설정을 먼저 완성합니다. 소스를 재빌드한 후, 현장 레시피의 `parts` 중 `part: pin` 항목만 다음으로 설정합니다.

```json
"pin_precision_preinsert": {"enabled": true, "gain": 0.5, "max_iterations": 8}
```

실행 명령은 기존 `random-cycle`과 같습니다. 이 옵션이 없거나 `enabled: false`면 기존 실행 경로를 유지합니다. 실제 SDK·카메라 입력과 모든 경로 검사를 통과해야 동작합니다. 새 옵션을 실행 허가나 성공 기록으로 사용하지 않습니다.

## 제어 순서

1. 기존 검사로 핀을 잡고 지그 아래 접근 자세로 이동합니다.
2. 실제 SDK 시계에서 최소 100ms, 최소 5개 서로 다른 상태를 읽습니다. 실제 TCP 변동이 25µm/0.5mrad 이내이고 원하는 관절값/TCP가 고정돼 있어야 다음으로 진행합니다. 최대 2초 뒤에도 안정되지 않으면 손을 잡은 채 중단합니다.
3. 새 RGB-D로 핀을 재추정하고 실제 Hand 파지 상태·새 G·하중을 확인합니다. 촬영은 정지 SDK 읽기 사이에 있어야 합니다. 이미지에 연결된 TCP와 후속 실제 TCP가 달라지면 중단합니다.
4. 중심·축 오차가 남으면 `command = FK(q_d)`, `actual = O_T_EE`를 같은 SDK 상태에서 얻어 `C × inverse(A)` 편차를 반영한 보정 목표를 만듭니다. 0.5 gain으로 갱신하며 한 번에 최대 8mm/0.1rad, 최대 8회입니다. 원하는/실제 TCP 편차가 2mm/0.01rad보다 크면 국소 보정을 시도하지 않습니다.
5. 실제 영상의 반경 방향 오차 ≤75µm, 축 오차 ≤3mrad, 축 구간 최대 반경 오차 ≤150µm를 모두 만족해야 축 방향 삽입 목표를 만듭니다. 지그 목표보다 35–55mm 아래에서만 정렬합니다.
6. 실제 명령 직전의 별도 새 영상에도 같은 정밀 기준을 적용합니다. 기존 1mm 일반 영상 일치 기준만 통과해서 핀을 넣지 않습니다. SDK/Hand 읽기로 이미지 TTL을 넘기거나 실제 TCP/원하는 관절값이 바뀌면 발행 전에 중단합니다.
7. 실제 조립 완료·클램프·개방·철수 후 유지 확인은 기존 RGB-D/SDK/실제 또는 수동 클램프 경로로 확인합니다. 정렬 통과를 조립 성공으로 처리하지 않습니다.

모든 보정 경로는 현재 새 G를 포함한 부품, 양팔·Hand·고정 설비·이미지 UNKNOWN·속도/추종/외력/heartbeat 검사에 다시 들어갑니다. 힘·마찰·질량·속도 제한을 바꾸지 않습니다. 반복해서 핀을 밀거나 실패한 접촉을 무시하는 후처리를 추가한 것은 아닙니다.

## 좌표와 검증 범위

현장 검출기는 현재 RGB-D **CAD body ICP**를 사용합니다. canonical 핀 CAD에서 몸체 원점→대칭축 중점은 `[0, -0.25mm, 0]`이므로 관측 포즈와 고정 지그 목표에 같은 변환을 적용합니다. 월드 Y를 임의로 옮기는 보정이 아닙니다. 물체 actor 좌표나 시뮬 관절 궤적을 실기 제어에 넣지 않습니다.

실제 SDK `O_T_EE`와 원하는 관절값의 모델 FK는 새 읽기 전용 `m80_read_state IP --with-model`에서 **같은 `readOnce` 상태**로 내보냅니다. 기존 상태 조회는 추가 모델 로딩을 하지 않습니다. FK는 실제 SDK의 `F_T_EE`/`EE_T_K`를 사용하며 셀 기저 보정을 똑같이 곱합니다.

Isaac 308의 네 번의 RGB-D end-circle 추정과 실제 시뮬 로봇 encoder 기록으로 변환식을 재생했습니다. 기존 물리축 표현과 새 CAD body 표현의 보정 목표 차이는 최대 `4.44e-16`입니다. 해당 시뮬 핀 구성 요소가 성공했지만 전체 세 부품 시험은 아니며, 시뮬에는 삽입 뒤 축 방향 깊이 보정 1회도 있었습니다.

현재 현장 ICP가 동일한 75µm 정밀도·수렴·가림 강인성을 확보했다고 검증하지 않았습니다. 실제 RealSense 금속 깊이 오차가 크면 이 기능은 정렬 실패로 중단할 수 있습니다. 시뮬 end-circle 검출기 전체를 실기로 포팅한 결과가 아닙니다.

장비 없이 포함된 기록과 변환식만 다시 검사하려면:

```bash
PYTHONPATH=src python tools/replay_pin_precision_component.py
```

이 재생은 로봇/SDK에 접속하지 않으며 실기 성공 증빙을 만들지 않습니다.
