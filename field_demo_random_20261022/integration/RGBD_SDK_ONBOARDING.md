# RGB-D + Franka SDK 기반 현장 연동 초안

이 복사본은 실제 SDK 저속 시험 경로와 RGB-D 연동을 구현한 현장 개발본이다. 실제 로봇 조립 성공과 전체 랜덤 집기 완주는 아직 확인하지 않았다. 원본 봉인 패키지는 보존했다. 목표 인계 시각은 2026-10-22 오전 11시 KST다.

## 입력과 실행 구조

`RealSense RGB-D → 실제 SDK 렌즈 모델로 정렬 → 픽셀·Depth에서 링 크기/중심/축/앞뒤 추정 → 현재 SDK TCP와 결합해 G=T_tcp_part 계산 → 현재 로봇 모델로 경로 생성 → 보수적 잔여 적재물·고정물·다른 팔·부품 충돌 검사 → 저속 실행 → 재촬영과 상태 검사`

매 프레임의 검출은 기하 기반이다. SAM이나 작업 중 LLM agent를 부르지 않는다. 소스에 알려진 것은 부품의 고정 CAD와 실측한 카메라·로봇·지그 보정값이다. 바구니 안 부품의 실제 위치·시뮬레이터 actor 좌표는 입력하지 않는다. 지그의 실측 목표 좌표는 탐색 ROI와 삽입 목표에 사용하며 현재 물체 자세를 대신하지 않는다.

## 없는 센서를 요구하지 않는다

| 확인 항목 | 사용 증거 |
|---|---|
| 파지 | 실제 Hand `is_grasped`/폭 + 새 RGB-D의 부품 크기·자세·손과의 상대 변환 |
| 양손 전달 | 주는 손이 유지하는 동안 받는 손의 실제 SDK 파지와 새 영상 확인 → 주는 손의 실제 개방 → 그 이후 촬영한 받는 손 영상으로 다시 확인 |
| 안착 | 지그 ROI의 현재 RGB-D 중심·축 오차 |
| 해제 후 유지 | 실제 손 개방 이후의 서로 다른 두 촬영에서 목표 자세가 최소 0.3초 유지되는지 확인 |
| 손 철수 후 완료 | 빈 손 TCP를 물체 위치로 가정하지 않고 고정 지그 ROI를 새로 촬영. 설치한 모든 부품을 다시 확인 |

부품별 PLC 파지·착좌·유지 입력은 필수가 아니다. 해당 이름은 호환되는 공정 내부 상태명이며 실제 판정 출처는 `SensorFacts` 기록에 남는다. 가려짐·크기 혼동·자세 오차·오래된 영상은 성공 처리하지 않는다.

클램프는 별도다. 실제 PLC가 있으면 `clamp_control.mode=actual_PLC`와 실주소·극성·읽기 확인을 설정한다. 없으면 `operator_manual`을 선택해 사람이 실제 클램프를 고정한 뒤 해당 부품명을 입력한다. 이 경우 자동 클램프라고 표시하지 않는다. 영상만으로 공압이나 클램프 압력을 측정했다고 주장하지 않는다.

## 고정 카메라

카메라 역할은 `basket`, `held_left`, `held_right`, `fixture`다. 하나의 고정 RGB-D 카메라가 모두 볼 수 있으면 같은 일련번호·같은 외부 보정을 공유할 수 있다. 같은 카메라를 역할마다 다른 위치에 있다고 선언할 수는 없다. 지그를 볼 수 없으면 현재 설정으로는 완료 확인이 안 된다.

`camera.py`는 실제 RealSense SDK의 렌즈 모델로 한 번만 좌표 맵을 만들고 새 촬영부터 적용한다. Depth 보간·홀 채우기를 하지 않는다. 정렬 후에도 실제 SDK XYZ를 유지하며 가장자리·무효 깊이와 재투영 오차를 점유 검사에 넘긴다. `depth_uncertainty_m`은 현장 거리·반사 금속의 오차를 고려한 명시적 상한이 필요하다. null을 0으로 바꾸어 통과시키지 않는다.

## 바구니 충돌 검사

`residual_occupancy`는 링으로 인식되지 않은 픽셀과 가려진 공간도 장애물로 남긴다. 전체 voxel의 투영 영역에서 유효 깊이로 관측한 앞쪽 공간만 free다. 검출이 하나라도 됐다고 나머지 바구니를 비우지 않는다.

선택한 링의 현재 관측 표면·CAD 표면 근처·한정된 접촉 영역을 모두 만족한 voxel만 지정된 손가락 접촉에 사용할 수 있다. 미관측 공간, 팔·손바닥·반대 팔·운반 부품은 이 예외를 쓰지 못한다. 보수적 점유가 경로를 막으면 다른 후보·더 잘 보이는 실제 뷰가 필요하다. 시야 뒤 공간을 임의 삭제하지 않는다. 실제 시야와 로봇 경로가 통과하는지는 별도 현장 확인이 필요하다.

## 하중과 중단

파지 후 들기 전, 새 G 관측 후, 전달 후 철수 전, 안착·유지·해제 후 철수 전에 정지 상태에서 실제 `setLoad`를 갱신하고 다시 읽는다. Hand tool과 물체 load를 구분하며 질량·COM·관성을 flange 좌표로 옮긴다. 프로파일·실제 tool/load·TCP·증빙이 맞지 않으면 이동하지 않는다. 전달에서 한 팔만 갱신됐다면 양팔 모두 추가 이동을 금지한다.

`cell_io_mode=SDK_stop`은 없는 PLC를 흉내 내지 않는다. 실제 native SDK의 오류·외력·추종·heartbeat 중단 검사는 유지하며 정지 시험 기록을 요구한다. 실제 셀 PLC가 있으면 `actual_PLC` 모드로 사용할 수 있다.

일반 관측 실패 시 활성 팔의 heartbeat를 정지하고 완료된 Hand 파지 명령을 취소하지 않는 정책이다. `Hand.stop()`을 보내고 파지가 유지된다고 표시하지 않는다. 마지막 파지 명령을 보존해도 마찰·전원·물체 유지가 보장되는 것은 아니다. SDK 상태를 기록하고 취소 상태를 유지한다. 자동 재개는 없다.

## 설정 순서

1. `init-random`으로 새 설정을 만들고 로봇 IP, base/TCP, 카메라 일련번호·외부 보정, 바구니/지그/작업 공간을 채운다.
2. 실제 손·케이블·설비를 포함하는 충돌 외피와 파지·전달·삽입 자세를 기록한다. 시뮬 좌표나 CSV를 실기에 복사하지 않는다.
3. `payload-profile.json`에 각 팔의 실제 tool/빈 load와 부품 질량·COM·관성을 채우고 레시피에 파일 해시를 넣는다.
4. 클램프 실제 PLC 또는 수동 확인 모드를 정한다. 지그 ROI는 `fixture_workspace_bounds_cell_m` 또는 측정된 held workspace 안에 있어야 한다.
5. 장치 상태·정지·손 파지 유지·단일 팔의 작은 저속 이동을 먼저 확인한다. field native commissioning 상한은 10%다. 시뮬의 95% 설정이 아니다.
6. 바구니 인식과 점유 결과, 단품 집기/전달, 지그 재관측을 확인한 뒤 전체 공정을 검토한다. 실제 생성된 접근·들기 경로와 단품 파지부터 확인한다. 일괄 실행 차단 대신 실제 입력·센서·하중·충돌·정지 조건이 맞을 때만 이동한다.

최신 오프라인 결과는 `reports/PAYLOAD_INTEGRATION_STATUS.json`에 정리한다. 합성 영상·가짜 SDK/Hand/클램프를 사용한 통합 검사는 실제 물리 조립 성공이 아니다.


## 첫 저속 이동·정지 시험

읽기 전용 확인은 `./field-demo run status --config site/random/site.json`으로 한다. 단순 첫 시험은 아래 별도 경로를 사용한다. 이전 정지 시험 통과 플래그를 요구하지 않으며, 실측 작업 공간·tool/load·비어 있는 단일 팔 시험 구역과 실제 보정값은 필요하다.

```bash
./field-demo commissioning-test --config site/random/site.json --side right --axis z --direction 1 --execute
./field-demo commissioning-test --config site/random/site.json --side left --axis z --direction 1 --execute
```

`axis/direction`은 **로봇 BASE 좌표**에서 실제로 1mm 움직일 여유가 있는 방향을 고른다. 위 z+는 예시이며 현장 설비/팔 자세에 따라 바꾼다. native 10% 이하 경로에서 실제 SDK CSV의 이동을 본 뒤 명시적 STOP을 보내고, native 수락·SDK 반환 순서와 실제 정지 `idle/dq`를 대조해 기록을 만든다. 손·클램프는 움직이지 않는다. 실패한 기록을 통과로 수정하지 않는다. 실제 PASS 기록을 두 팔의 `commissioning_record`/`stop_tested` 증빙에 사용한다. 안전 등급 비상정지 인증을 대신하는 시험은 아니다.

## 단품부터 실제 실행

```bash
./field-demo random-cycle --recipe site/random/random-cycle.json --validate
./field-demo random-cycle --recipe site/random/random-cycle.json --single-pick ring1 --execute --output-dir field-logs/pick-large
./field-demo random-cycle --recipe site/random/random-cycle.json --single-pick ring2 --execute --output-dir field-logs/pick-small
```

`--single-pick`은 해당 링을 집고 들고 재관측한 뒤 팔이 정지한 채 파지를 유지하고 끝난다. 자동 전달·삽입·놓기는 하지 않는다. 정상 종료도 손이 빈 상태라는 뜻은 아니므로 SDK와 실제 물체를 확인한다. 전체 공정은 같은 명령에서 `--single-pick`을 생략한다. 실제 물체가 잡힌 채 새 공정을 재시작하면 초기 빈 손/하중 검사가 거부한다.

엄격한 점유 검사로 접근이 불가능한 경우에만 `random-motion.json`의 명시적 `bounded_loose_stock_contact`를 설정한다. 템플릿의 예시는 비활성 상태다. 링 두 종류·최대 10개만 있는 실제 바구니 내부, 실제 손가락 캡슐 이름/인덱스, 실제 native 파일과 정지 시험 해시를 채운다. 알려지지 않은 공간을 비었다고 바꾸는 기능이 아니다.

이 접촉 모드는 `inventory_inspection`도 필요하다. 각 팔의 실측 `T_flange_hand`, 같은 카메라에서 링 양쪽 면을 볼 실제 상대 TCP 회전, 최대 불확실 적재물 외피, 기존 바구니 위 반환 포즈/영역, 빈 손 관측 회전을 기록한다. 모든 회전·반환은 실제 전체 로봇/고정물/반대 팔/부품 경로 검사를 통과해야 한다. 하나라도 가려지거나 막히면 파지를 유지하며 중단한다. 물리적으로 잡기 전 숨은 추가 부품의 질량은 알 수 없으므로 초기 클래스 하중을 다중 부품 하중 검증으로 해석하지 않는다.

최신 GPU/cuRobo 시뮬 정책은 별도 H 경로에서 시험 중이다. 이 실기 복사본은 native libfranka 모델로 현재 상태에서 경로를 만들며, 최신 시뮬 정책 전체나 속도 성능을 가져왔다고 주장하지 않는다.

## NEXT 추가분: 실제 바닥 접촉에서 짧게 들기

선택적 `stock_departure`는 위로 최대 70mm의 첫 접촉 이탈을 구분한다. 첫 들기는 원래 바닥/다른 링과 접촉하므로 충돌 없는 이동으로 표시하지 않는다. 명시적 설정 예시는 `random-motion.json`의 `bounded_loose_stock_departure_example`에 있으며 실제 사용은 `phases.stock_departure.bounded_loose_stock_departure`에 연결한다. 동일한 실측 재고/바구니/손가락/실제 실행 파일/정지 증빙을 사용한다.

`support_floor`는 실제 측정한 바닥 원점·법선·장애물 이름·정렬 오차·영상 추정 보정 상한/깊이 오차 상한을 담는다. 처음 영상 추정 CAD가 이 오차 안에서 바닥을 조금 침범할 때만 추정 자세를 위로 보정하고 원래 오차/보정량을 기록한다. 실제 물체를 이동시키거나, 높게 놓인 링을 바닥으로 내리지 않는다. 보정 뒤 최초 하중도 새 추정 G로 설정한다.

발행 FK의 모든 샘플에서 전체 고정 CAD 정점이 바닥 위에 있고 점점 이탈하는지 검사한다. 이 증명이 있을 때만 선택 부품의 보수적 외피가 이름이 일치하는 바닥 상판과 겹치는 것을 접촉 기술로 처리한다. 바닥 OBB의 윗면과 측정 평면도 일치해야 한다. 손가락/손바닥/팔/벽에는 이 바닥 예외가 없다. 실제 추종·외력·heartbeat 감시는 그대로다.

저장된 시뮬 RGB-D 세 시점에서 생성한 접근과 40/70mm 단기 이탈의 제한된 구성요소 검사가 통과했다. 전체 실기 SDK 외피·실제 파지·단일 물리 카메라 완주가 통과한 것은 아니다. `reports/bounded-stock-component-acceptance-summary.json`의 범위를 확인한다.
