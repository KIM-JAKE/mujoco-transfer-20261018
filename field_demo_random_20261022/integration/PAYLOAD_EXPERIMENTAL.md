# 이번 복사본의 실제 연동 범위

이 폴더는 원본 v128을 보존하고 만든 별도 개발 복사본이다. 현장 SDK 실행 경로와 단품 시험 명령은 사용할 수 있게 구현했다. 실제 로봇 조립 성공·랜덤 바구니 전체 완주·현장 작업시간은 검증하지 않았다. 최신 사용 순서는 [RGB-D + SDK 온보딩](RGBD_SDK_ONBOARDING.md)을 따른다.

## 하중

실제 Hand `is_grasped`와 새 RGB-D의 상대 자세 G를 확인한 후, 팔이 정지한 경계에서 `setLoad`를 쓰고 읽기 결과를 대조한다. 다음은 별도 데이터다.

- `m_ee`: 실제 Hand/도구의 질량·COM·관성. 물체 하중에 다시 더하지 않는다.
- `m_load`: 빈 어댑터 하중 + 실제 파지 물체. 물체 CAD 프레임의 COM·관성을 현재 SDK flange/TCP와 영상 G로 변환한다.
- 질량·COM·관성·좌표계·증빙·파일 해시는 명시적으로 채워야 한다. null을 가짜 기본값으로 채우지 않는다.

파지 뒤 들기 전, 새 G 관측 뒤, 양손 전달 뒤, 안착·클램프·해제·영상 유지 확인 뒤 하중을 전환한다. 받는 팔과 주는 팔 갱신은 원자적이지 않으므로 한쪽만 성공해도 양팔 추가 이동을 막는다. 실행 중인 `control()` 콜백에서 설정 함수를 호출하지 않는다.

## 영상과 SDK만으로 부품 상태 확인

부품 파지/착좌/유지용 PLC 센서는 요구하지 않는다. 실제 SDK 손 상태와 새 RGB-D 크기·중심·축·상대 자세를 사용한다. 양손 전달은 주는 손이 아직 잡고 있을 때 받는 손을 확인한 뒤 개방하고, 그 이후 촬영한 받는 손 영상으로 재확인한다. 지그는 실측 목표 ROI에서 새로 관측하며, 손 철수 뒤 설치한 모든 부품을 다시 확인한다.

클램프는 실제 PLC 또는 명시적인 작업자 수동 고정 확인이다. 수동 확인을 자동 클램프나 압력 센서로 표시하지 않는다.

## 느슨한 적재물 접촉과 실패 처리

기본 점유 검사는 엄격하다. UNKNOWN은 장애물로 남는다. 선택적으로 설정하는 `bounded_loose_stock_contact`는 실측 바구니 내부의 지정 손가락만 느슨한 링 재고와 접촉할 수 있게 한다. 팔·손바닥·반대 팔·운반 물체·고정 벽은 예외가 아니다. 실제 native 5N/1Nm 외력 중단, 250ms heartbeat, 실행 파일과 실제 정지 시험 해시를 함께 검증한다.

이 모드는 링을 든 뒤 실제로 방향을 바꾸어 같은 고정 카메라에서 양쪽 면을 관측한다. 넓은 ROI의 모든 깊이를 단일 CAD와 대조하고, 추가 물체·가려진 적층·미관측 깊이·불안정한 G를 성공 처리하지 않는다. 알려진 로봇 표면 제외는 공식 Hand CAD를 현재 실제 SDK TCP/F_T_EE/폭과 실측 장착 변환으로 배치한 표면 일치만 사용한다.

검증되지 않은 파지는 보수적 적재물 외피와 전체 로봇 검사를 통과한 경로로 기존 바구니 위에 반환한다. 실측 반환 영역 안인지 확인한 뒤 손을 열고, 서로 다른 두 실제 뷰에서 빈 손이 확인된 뒤 빈 하중으로 전환한다. 카메라나 경로가 없으면 반환을 강행하지 않고 완료된 파지 명령을 보존하며 중단한다.

**첫 들기 전에는 숨은 추가 부품의 개수·정확한 질량/COM을 알 수 없다.** 초기 하중은 검출된 선택 클래스 기준이고 실제 SDK 외력 검사가 유지된다. 이것은 보이지 않는 추가 물체에 대한 하중 인증이 아니다. 실제 생성된 접근+들기 경로와 단품 파지 시험이 아직 통과하지 않은 현장에서는 전체 랜덤 조립 준비 완료라고 판단하면 안 된다.

## 명시적 현장 실행

`random-cycle --execute`의 일괄 차단은 제거했다. 실제 측정 입력, SDK 상태, 카메라/점유, 경로, 하중, 정지 조건이 모두 맞을 때 기존 native 10% commissioning 상한으로 실행한다. `--single-pick ring1` 또는 `ring2`는 해당 링을 들고 검사한 뒤 팔을 정지한 채 잡고 끝낸다. 전달·삽입·자동 개방은 하지 않는다. 내경에서 벌려 잡는 시뮬 파지는 실기 지원으로 간주하지 않으며 실제 실행기는 큰 개방 폭에서 닫는 외경 파지만 허용한다.

일반 중단에서 `Hand.stop()`을 무조건 보내 파지 명령을 취소하지 않는다. 실제 손 상태를 별도 스레드에서 읽고 샘플이 200ms 이상 오래되거나 오류가 나면 이동을 막는다. 완료된 파지 보존과 실제 물체 유지 보장은 다르며 자동 재개는 없다.

## 오프라인 증거

`reports/PAYLOAD_INTEGRATION_STATUS.json`과 `reports/*OFFLINE_CHECK.log`를 확인한다. 실제 상태머신/하중 계산기를 가짜 장치 경계에 연결한 전체 3개 순서 검사, 쓰기 실패·부분 전달 실패, 잘못된 실제 tool/load, null 입력, 오래된 손 상태, 제한된 적재물 접촉, 영상 단일 물체/빈 손 증거와 반환 순서 검사가 포함된다. 가짜 장치 테스트와 저장 RGB-D 재생은 실제 로봇 성공이 아니다. `stabilization/v128` 성공 기록은 보존한 이전 시뮬 참조이며 최신 시뮬 정책이 실기에 자동 이식되었다는 뜻이 아니다.
