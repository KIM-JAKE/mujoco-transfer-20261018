# M80: contact-driven PhysX assembly

**최신 원본 배치 결과:** 센서 장착 위치·본체·tail을 유지하고, 빛의 경로를 나타내는 광축 solid만 접촉에서 제외했다. `contact-original-sensors-01`은 파지·조립·버튼 기능과 FR3 관절 한도 검사 통과, 주기 15.129167초로 시간 목표 실패다. [검증 근거](reports/original-sensors-01/acceptance.json), [실기 미검증 조건](fieldkit/README.md)을 먼저 확인한다. 아래 14.729초는 위치를 변경했던 이전 시험이며 원본 배치 실기 성능이 아니다.

**이전 위치 변경 시험 기록: `runs/contact-under15-07`에서 15초 미만, 95% 명령 상한, 실제 FR3 운동학 한도와 조립·버튼을 모두 통과했다.** 초기 안정화 0.5초를 제외한 실제 공정 시간은 **14.729167초**다. 이전 22.881250초보다 **35.63% 단축**했다. 시간은 세 부품 해제 후 버튼의 실제 1.8mm 이상 100ms 누름 완료까지 측정한다. 최종 유지 검증은 별도로 수행한다. 기존 8.060초 목표는 아직 미달이다.

**FR3 실기 한도 감사 결과: 7.908초 실행은 FR3에서 실행 가능한 궤적이 아니다.** `runs/contact-fast-30/fr3-motion-audit.json`에서 측정 관절 위치의 30Hz 차분 기준 왼팔 2번 관절 속도 4.226rad/s(공식 명목 상한 2.62rad/s), 오른팔 3번 관절 4.497rad/s(2.62rad/s), 오른팔 7번 관절 가속도 57.812rad/s²(10rad/s²)를 확인했다. 과거 실행의 `physical_simulation_pass`는 파지·조립·버튼·충돌 조건의 통과만 의미하며 FR3 속도·가속도·jerk 준수를 포함하지 않는다. 새로운 `--fr3-limits` 실행은 FR3 한도 판정도 별도로 요구한다. 영상은 측정 시각의 1배속이지만 궤적 자체가 실기 한도를 초과한다. 구간별 시간 단축 후 공식 한도를 재검증하지 않은 점을 정정한다.

한도 출처: [Franka 공식 FCI 규격](https://frankarobotics.github.io/docs/robot_specifications.html), 2026-10-18 확인. 과거 구현에는 관절 토크 상한 87/12Nm를 주었으나 속도·가속도·jerk 및 위치 의존 속도 제한을 만족시키는 궤적 생성기/수락 조건이 없었다. 실기 가능한 주기 시간은 해당 제약을 적용하고 PhysX에서 재실행한 뒤 다시 측정해야 한다. 30Hz 기록은 모든 순간 피크를 담지 못하므로, 본 감사는 초과 검출이며 실기 가능성 인증은 아니다.

감사를 다시 실행하려면 호스트의 복원된 `.venv` Python으로 `audit_fr3_motion_limits.py runs/contact-fast-30`을 실행한다. 초과 검출 시 종료 코드 1을 반환하고 해당 실행에 `fr3-motion-audit.json`을 쓴다.

기존 8.060초 기록에서 모터 기준을 가져오되, 부품은 PhysX의 중력·충돌·마찰로 움직인다. MuJoCo는 정기구학/Jacobian 계산에만 사용한다. 부품의 위치·속도는 초기화 때만 설정한다. 이후 부품과 손/지그를 연결하는 고정 관절, 흡착, 부품의 강제 위치 이동은 없다.

이 구현은 **수정한 시험 설비 배치와 가정한 클램프의 기능 검증**이다. 원본 CAD에는 금속 레일 간섭이 남아 있으며 실물 공정의 인증을 의미하지 않는다. 최종 통과 여부는 각 실행의 `acceptance.json`으로 판단한다. 영상 생성이나 `completed_probe` 상태만으로 조립 성공이라고 판단하지 않는다.

2026-10-18 과거 제한 미적용 실행 `runs/contact-fast-30`: **`physical_simulation_pass: true`, 실제 공정 7.908333초**. 원본 8.060333초 기준보다 약 0.152초 빠르다. 세 부품 모두 운반 중 양측 패드 접촉 비율 100%, 클램프 고정·손 해제·유지 검사를 통과했다. 해제 후 최대 위치 오차는 ring1 0.0612mm, ring2 0.0140mm, pin 0.00823mm다. 의도치 않은 로봇 접촉은 0N이며 버튼 최대 스트로크는 2.200mm다. 버튼의 순간 접촉 피크 약 90.0N은 그대로 기록하며 실물의 허용 힘을 인증하지 않는다. 최종 실행은 단일 에피소드 검증이며 반복 성공률 시험은 포함하지 않는다.

## FR3 제한 적용 실행

### 15초 미만 최적화 — 전체 물리 검증 통과

기본 실행은 `prepare_fr3_timing.py --target-15`와 `test_contact_task.py --target-15 --efficient-timing`이다. 명령 상한과 실제 관절 한도, 강체 접촉, 부품 정렬·파지·고정·해제 기준을 그대로 검사하며 실제 공정 시간 **15초 미만도 필수**다. 검증된 실행은 `contact-under15-07`, 공정 14.729167초다. `test_under15_acceptance.py`는 다른 모든 조건이 정상인 이전 22.88초 실행도 새 시간 조건에서는 거부한다.

공간 경로를 유지한 채 구간 안의 제한 초과 지점만 국소적으로 늘려 계획 길이를 13.246486초로 줄였다. 빈 오른팔 복귀에는 실제 추종 가속도를 위한 1.08배 시간 여유를 추가했다. 팔 구동 강성 12000Nm/rad, 토크 상한 87/12Nm는 유지하며 시험 제어기의 감쇠를 왼팔 600·오른팔 1800Nms/rad로 조정했다. 이 수치는 PhysX 구동기 설정이며 실기 FR3 제어기 검증값이 아니다.

링 삽입의 자세 보정 gain은 0.24다. 핀 정밀 단계는 실제 XY·회전 오차를 사용하며 착좌 전 수직 오차에는 손 추종 지연 보상을 적용한다. 핀 gain 0.12, 최대 보정 증분 0.00024rad/120Hz이며 별도 보정기의 속도·가속도·jerk 상한 0.025rad/s·0.4rad/s²·50rad/s³는 유지한다. 실제 월드 좌표의 25µm 정렬 확인, 0.45mm 착좌와 접촉 보호는 유지한다. 핀 접근 최소 0.85초, 마지막 5mm 최소 0.65초를 배정한다.

클램프는 실제 착좌 허용 범위에 들어오면 닫기를 시작하며 가정한 닫힘 램프를 0.08초로 줄였다. 죠의 형상·질량·최대 힘은 같고 최소 120ms 양측 접촉 확인 후에만 손을 연다. 이는 실측 전 액추에이터 가정의 변경이다. 버튼 누름 최소 0.5초와 패드 목표 1.95mm를 사용해 2.2mm 끝단 충격을 피하며, 실제 스트로크 1.8mm 이상 100ms 기준은 유지한다.

`fr3-under15-profile.npz/json`과 구현·기준 경로·입력의 실행별 사본 및 해시를 보존한다. 첫 세 후보는 실제 관절 가속도 초과로 중단됐다. `contact-under15-04`는 물리 실행 전 오래된 입력을 감지해 취소했다. `contact-under15-05`는 조립·버튼·FR3 한도를 통과했으나 15.7125초로 시간 기준에서 실패했다. `contact-under15-06`은 14.995833초로 전체 조건을 통과했지만 시간 여유가 약 4ms여서 접근·버튼 구간을 추가 최적화했다. 실패 결과를 성공 영상으로 사용하지 않는다.

이전 22.88초 모드는 `contact_pipeline.py --baseline-timing --output ...`, 44.54초 보수 모드는 `--conservative-timing`으로 선택한다. 아래 22.88초·보수 모드 설명은 보존된 이전 설정이다.

### 이전 22.88초 모드 — 전체 물리 검증 통과

이전 22.88초 모드는 `prepare_fr3_timing.py`에서 FR3 위치 의존 양방향 속도·가속도·jerk의 **95%를 명령 상한**으로 사용한다. 모든 관절이 동시에 95%로 움직인다는 뜻은 아니다. 경로 길이, 관절 자세와 접촉 조건에 따라 먼저 도달하는 제약이 속도를 결정한다. 기준 가속도에는 9.1rad/s²를 배정하고 실시간 물체 보정에 0.4rad/s²를 남겨 합계 9.5rad/s² 이내로 검사한다. jerk는 기준 4700rad/s³와 보정 50rad/s³, 합계 4750rad/s³다. 독립 판정기가 합성 명령의 95% 상한과 실제 측정값의 공식 한도를 따로 검사한다.

두 팔의 공간 경로와 동시 작업 관계를 유지하면서 구간 안의 시간 배분을 다시 계산한다. 곡률이 큰 짧은 지점 때문에 이동 구간 전체를 느리게 하던 문제를 줄이고, 파지·정렬·착좌·고정·손 해제 확인 경계에서 정지한다. 계획된 기본 길이는 21.345초이며 접촉 확인 대기는 별도다. 검증된 실제 공정 시간은 22.881250초다. 계획 값만으로 공정 성공이나 실제 완료 시간을 선언하지 않는다.

정밀 접촉은 팔의 최고 속도와 별도다. 링 최초 파지의 그리퍼 구동 기준 상한은 0.14rad/s, 핀 파지는 0.25rad/s로 낮춘다. 핀의 정밀 접근은 최소 4초, 마지막 5mm는 최소 2초로 둔다. 버튼 접근·누름·유지를 구분하고, 누름에는 최소 1.2초를 배정해 2.2mm 기계적 끝단의 충격을 피한다. 모터 명령만 빠르게 해도 강체 접촉 충격이 실제 관절 가속도·jerk를 초과할 수 있으므로 실패한 후보를 기록하며 조건을 조정한다. `contact-fr3-95-01`은 핀 접근 중 실제 가속도 20.806rad/s², `contact-fr3-95-02`는 핀 파지 순간 실제 jerk 5863.162rad/s³로 중단됐다. `contact-fr3-95-03`은 세 부품의 파지·삽입·클램프·손 해제까지 통과했으나 버튼 끝단 접촉 순간 가속도 10.536rad/s²·jerk 5611.161rad/s³로 중단됐다. 이 후보들은 성공 결과가 아니다.

시간 배분 최적화는 Kit과 별도 프로세스에서 수행한다. `fr3-efficient-profile.npz/json`에는 위상 곡선, 입력 fingerprint와 95% 계획 예산을 저장하고 실행별 사본과 SHA-256을 보존한다. 기록 검사는 이 사본의 해시도 확인한다. `test_efficient_fr3_profile.py`는 전체 명령과 중간 접촉 대기를 실행하며 95% 상한을 확인한다. `test_fr3_acceptance.py`는 공식 한도 안이지만 95% 예산을 넘는 명령도 별도로 거부하는지 검사한다.

이전 전체 통과본 `contact-fr3-09`의 보수적인 44.535초 시간 배분은 `contact_pipeline.py --conservative-timing --output ...`으로 선택할 수 있다. 아래 70%·4rad/s² 설명은 그 보수 모드에 해당한다.

`run_contact.sh`는 `--fr3-limits`를 기본 적용한다. 제한 미적용 궤적은 공간 경로의 기준으로 사용하며, 실제 시간 배분은 `fr3_reference_profile.py`에서 다시 계산한다. 원래 `--speed` 값으로 영상을 배속하지 않는다.

두 팔의 관절 공간 경로를 C2 연속 spline으로 만들고, 두 팔의 모든 작업 단계 경계를 합친 공통 시간표에 minimum-jerk 위상 곡선을 배정한다. 각 경계에서 양팔의 기준 속도와 가속도가 0이 되므로 파지·착좌·클램프·손 해제 확인을 기다릴 때도 경로를 벗어나며 급정지하지 않는다. 시간 배분은 위치 의존 속도 범위의 70%, 가속도 4rad/s², jerk 800rad/s³를 기준으로 계산하며 관절 위치에 ±0.015rad의 보정 여유를 둔다. 그리퍼 구동기의 공간 기준도 시간 배분에 포함한다. 생성된 공통 시간표의 기본 길이는 43.248초이며 실제 접촉 대기는 추가된다. 최단 시간으로 최적화한 결과는 아니다.

핀을 지그에 넣기 전에는 실제 XY 오차 25µm, 높이 오차 0.3mm, 자세 오차 0.0015rad 이내인지 확인한다. 정렬 및 삽입 구간의 물체 보정은 모터 지연 보상 좌표가 아닌 실제 월드 좌표 측정값을 사용한다. 삽입 접근 구간은 최소 4초, 마지막 5mm는 최소 5초로 배분한다. 예상하지 못한 구간 중간의 힘 정지가 필요하면 명령을 갑자기 멈추는 대신 해당 시험을 중단하고 실패로 보존한다.

삽입 중 물체 오차와 버튼 보정만 별도 Ruckig 위치 제어기로 부드럽게 만든 뒤 기준 명령에 더한다. 보정 속도·가속도·jerk 상한은 각각 0.025rad/s, 0.4rad/s², 50rad/s³다. 최종 합성된 모든 FR3 팔 명령에서 공식 관절 위치·위치 의존 속도·가속도 10rad/s²·jerk 5000rad/s³ 및 속도 명령의 연속성을 480Hz로 검사한다. 로봇/부품의 실제 위치·속도를 강제로 제한하는 방식은 사용하지 않는다. 자세·접촉 피드백은 120Hz이며 FR3 팔과 그리퍼 구동 명령은 모두 480Hz로 출력한다. 링을 처음 잡는 구간은 그리퍼 구동 기준 속도 0.15rad/s와 최대 토크 0.75Nm로 부드럽게 닫는다. 양측 파지 접촉을 확인한 뒤 최대 유지 토크 5Nm로 복귀한다. 실제 FR3 관절 가속도·jerk도 매 스텝 감시하고 초과 시 즉시 진단 기록을 저장해 중단한다.

`fr3_motion_worker.py`는 Kit과의 C++ 심볼 충돌을 피하도록 Ruckig 0.12.2 계산을 별도 프로세스에서 수행한다. 실행별 코드 사본을 사용하고 바이너리 파이프로 매 스텝 보정을 주고받는다. 이전에 연구한 관절별 속도 추종 제어기는 경로를 벗어날 수 있어 기본 실행에서 사용하지 않는다.

`prepare_fr3_posture.py`는 검증된 접촉 경로의 손 자세를 보존하면서 버튼 접근 중 오른팔 1번 관절을 최대 −0.30rad 보정한다. 오른팔 2번 관절 최솟값은 −1.8286에서 −1.7003rad로 바뀌며, 416개 표본에서 전체 시험 설비·설치된 링·공급 지지대·자기/양팔 충돌 검사를 통과했다. 결과는 `arm-posture-fr3.npz/json`으로 분리해 과거 결과를 보존한다.

물체 자세 보정은 실제 손에 대한 물체의 상대 자세를 목표 손 좌표계로 옮겨 계산한다. 모터 추종 지연을 물체 보정이 다시 누적하지 않도록 하기 위함이다. 실제 파지 미끄러짐은 계속 검출하며, 착좌·클램프·손 해제 판정과 25mm 추종 오차 중단 기준은 실제 월드 좌표 측정값을 사용한다. 제한 적용 모드의 자세 보정 gain은 0.04, 관절별 증분 상한은 120Hz당 0.00012rad다.

`joint-motion.npz`에는 480Hz 명령 위치·속도·가속도와 실제 관절 위치·속도를 저장한다. `evaluate_fr3_limits.py RUN`은 명령과 실제 측정값의 위치·위치 의존 속도·가속도·jerk를 독립 검사한다. 어느 쪽이든 실패하면 `fr3-limits.json` 및 최종 조립 판정은 실패한다. 1kHz FCI 실기 실행, 토크 변화율, 실측 payload 및 접촉 재질의 인증과는 구분한다. `plot_fr3_limits.py RUN`은 평활화 없이 최대 한도 사용률 그래프를 만든다.

검사:

- `test_fr3_reference_profile.py`: 전체 공통 경로, 중간 접촉 대기, 별도 프로세스의 보정 생성기를 검사한다.
- `test_fr3_feedback.py`: 모터 추종 지연과 실제 1mm 파지 미끄러짐이 구분되는지 검사한다.
- `test_fr3_acceptance.py`: 매끄러운 알려진 신호를 통과시키고 실제 관절 기록의 속도 spike를 독립적으로 거부하는지 검사한다.

연구 실행은 보존한다. `contact-fr3-01`은 C++ 라이브러리 충돌, `contact-fr3-02`는 추종 오차 25mm 초과로 중단됐다. `contact-fr3-03`은 세 부품과 버튼 조건을 통과했지만 경로 이탈에 따른 설비 접촉과 실제 가속도·jerk 초과로 불합격이다. `contact-fr3-04`에서 의도치 않은 설비 접촉은 0N이 됐으나 핀 정렬 불량으로 힘 보호 정지가 발생했고 실제 가속도·jerk도 일부 초과해 불합격이다. `contact-fr3-05`는 조립·버튼과 설비 접촉 0N을 확인했으나 초기 작은 링 파지의 순간 가속도·jerk 초과로 불합격이다. `contact-fr3-06-grasp`와 `07-grasp`의 짧은 진단 후 그리퍼 명령을 480Hz로 바꾸고 닫힘 속도·토크를 줄였다. `contact-fr3-08-grasp`에서 초기 파지 구간의 실제 최대 가속도 7.104rad/s², jerk 4940.120rad/s³로 통과했으며, 같은 제어의 전체 실행 `contact-fr3-09`에서 조립·버튼·FR3 한도·설비 접촉 검사를 모두 통과했다. 짧은 진단을 전체 작업의 성공으로 취급하지 않는다.

## 작업 순서와 제어

1. 왼손으로 ring2(작은 링)를 잡고 삽입한다. 클램프의 실제 접촉을 확인한 다음 손을 연다.
2. 오른손은 ring1(큰 링)을 삽입하고 같은 순서로 놓는다.
3. 왼손은 핀을 들어 픽업 위치에서 기다린다. 오른손이 링 지그를 벗어나 버튼 앞까지 이동하면 핀 운반을 계속한다.
4. 핀을 삽입하고 클램프 접촉을 확인한 뒤 놓는다. 마지막으로 오른손의 실제 패드가 스프링 버튼을 누른다. 손을 놓을 때는 패드 접촉이 사라지고 구동기가 열린 뒤 복귀를 시작한다. 핀 조립 뒤 왼손은 열린 상태로 자세를 유지한다.

`task_timing_fast.py`는 두 팔의 동시 동작을 유지하고, 팔 교차를 피하도록 핀을 든 왼손에 짧은 대기만 추가한다. 기준 모터 경로는 약 6.796초이며 이동 구간은 원본 시간의 1.6배 속도, 핀 삽입 구간은 0.6배 속도, 버튼 구간은 1.9배 속도로 배분한다. 핀 픽업의 마지막 구간은 0.8배 속도로 별도 배분하고, 핀 삽입 직전에 150ms 정렬 대기를 둔다. 이는 모터 기준의 시간 배분이며 영상은 실제 측정 시각으로 재생한다. 접촉 검증 대기는 실제 실행 시간에 추가된다. 버튼의 실제 100ms 누름 확인 시각에서 초기 안정화 0.5초를 뺀 값을 공정 시간으로 기록한다. **과거 제한 미적용 실행은 공정 시간 8.060초 이하도 통과 조건**이었다. 새로운 `--fr3-limits` 실행은 FR3 한도와 실제 조립 검증을 우선하며, 기존 8.060초 목표의 달성 여부는 별도로 보고한다. 영상 배속으로 시간을 줄이지 않는다. 초기 안정화와 최종 1.5초 유지 검증은 공정 시간과 구분한다.

과거 느린 진단은 `task_timing.py`와 `--retimed --speed 4`로 보존한다. 47초 진단에서는 세 부품 삽입·클램프와 버튼 접촉을 확인했지만 핀의 순간 속도 한도를 넘겨 전체 판정은 실패했다. 이를 8초 성공 결과로 취급하지 않는다.

팔꿈치 자세는 손의 조립 자세를 유지하며 여유 자유도로 보정한다. 빈 오른손은 레일을 벗어날 때 전방 최대 50mm, 하방 최대 60mm 우회하고, 하강 보정은 원본 시각 6.5초까지 해제한다. 복귀 우회는 링에서 벗어난 원본 시각 5.95초 이후에 시작한다. 설치된 두 링도 로봇 경로의 장애물로 검사한다. 핀은 지그와 XY가 정렬될 때까지 접근 높이를 최대 4mm 낮춘 뒤 수직 삽입한다. `plan_right_posture.py --fast`가 설비·자기·양팔 충돌을 표본 검사한다. 팔-설비 여유 3mm, 그리퍼-설비 여유 0.1mm를 사용하며 실제 실행 접촉도 별도로 검사한다.

## 금속 레일과 CAD 제한

사용자는 아래 세 줄이 단단한 금속 가이드·레일임을 확인했다. 모든 레일은 강체 충돌을 유지한다. 원본 최종 목표에서 부품과 레일이 겹쳐, 별도 시험 레이어에서 외형과 충돌 형상을 함께 이동했다.

| 대상 | 원본 간섭 레일 ID | 시험 배치의 세계 Y 이동 |
| --- | --- | ---: |
| ring1 | 0373, 0382 | −30mm |
| ring2 | 0369, 0380 | +12mm |
| pin | 0371, 0384 | −60mm |

**이는 가상 시험 배치다. 실물 설치 가능 위치나 승인된 기계 수정안이 아니다.** 원본 CAD 파일을 수정하지 않고 `configuration.usda`의 시험 레이어에만 반영한다. 레일과 프레임의 체결 구조/강성/정적 조립까지 설계 검증한 것은 아니다.

`audit_cad_interference.py`는 원본/수정 배치에서 최종 부품과 CAD 삼각형의 교차를 비교한다. 핀-지그 0554의 삼각형 접촉은 별도로 남겨 두며, `audit_pin_brep.py`의 정확한 BRep Boolean 검사에서는 핀 4개 구성품과 지그 사이 고체 교차 체적이 모두 0mm³였다. 이는 접촉·공차·삽입 경로 또는 실물의 인증과 구분한다.

## 클램프와 접촉 모델

사용자가 확인한 공압·기계식 클램프를 기능 모델로 추가했다. 죠의 접촉 패드는 고무 마찰 계수로 가정한다. 링마다 내부 확장 죠 3개, 핀에는 외부 죠 2개를 사용한다. 각 죠는 질량 40g의 강체이며 프리즘 관절과 힘 제한 구동기로 움직인다. 삽입 위치 확인 → 기본 15초 목표 모드는 0.08초(이전 모드는 링 0.2초·핀 0.1초)에 걸쳐 닫기 → 최소 120ms 동안 양측 접촉이 80% 이상 측정되는지 확인 → 로봇 손 열기 순서다.

| 가정한 파라미터 | 값 |
| --- | --- |
| 링 죠 스트로크 / 죠당 구동력 상한 | 2.0–2.4mm / 5N |
| 핀 죠 스트로크 / 죠당 구동력 상한 | 4.7mm / 3N |
| 죠 강성 / 감쇠 | 40,000N/m / 80Ns/m |
| 강철 정/동마찰 | 0.60 / 0.51 |
| 고무 패드 정/동마찰 | 1.00 / 0.85 |
| 버튼 질량 / 스프링 / 최대 스트로크 | 15g / 1,500N/m / 2.2mm |

죠의 형상·구동력·마찰과 버튼 파라미터는 실측 전의 가정이다. 핀 공급부는 원본의 upright pin socket 설명을 따라 내경 5.2mm·외경 10mm·높이 6mm의 수동 지지 슬리브로 모델링한다. 치수는 가정이며 바닥 쪽 축만 안내한다. 위로 12mm 들어 올리면 가이드에서 빠져나온다. 소켓과 핀을 연결하는 관절은 없다. 패드와 접촉 강성도 실측 전의 가정이다. 고정 지그만으로는 링이 중력에 의해 떨어지는 음성 대조 시험도 보존한다. 죠와 그 내부 하우징 사이에는 기구 내부 충돌 필터가 있으며, 죠-부품 및 죠-로봇 충돌은 활성화한다.

원본 BRep를 1µm 편차로 삼각화하고, 동적 링에는 해상도 768, 핀의 오목한 외피에는 해상도 512의 SDF 충돌을 쓴다. 핀의 오목한 끝 부품 0558도 원본의 닫힌 삼각형 Mesh를 SDF 512로 사용한다. 기존 볼록 껍질은 실제 Mesh 체적의 5.73배 공간을 메워 손가락 접촉면을 왜곡했다. 닫힌 원본 Mesh인 내부 스프링 0555도 SDF 512를 사용한다. 축 구성품 0556은 원본 볼록 충돌 근사를 유지한다. 해당 BRep 삼각화는 닫힘 검증을 통과하지 못해 미검증 SDF로 바꾸지 않았다. 클램프 패드에는 SDF 수치 진동을 줄이는 유한 접촉 강성 1,000,000N/m·감쇠 100Ns/m을 사용한다. 금속 삽입면은 강체 접촉으로 유지한다. 이 값도 실측 재질 인증이 아닌 수치 모델의 가정이며 강체 부품/레일의 형상은 유지한다. 로봇 패드와 부품 사이 접촉에는 이 유연성을 적용하지 않는다. 버튼은 원래 가상 손끝 대신 실제 패드 끝으로 접근한다. 독립 시험에서 약 2.08mm 스트로크와 3.13N 접촉을 확인했으며, 전체 작업에서도 별도로 판정한다.

영상에서는 실제 CAD 고리 두 개와 핀을 파랑·주황·초록으로 구분한다. 가져온 고리 Mesh의 `purpose=guide` 때문에 렌더에서 빠지던 문제를 `default`로 수정했다. 물체의 형상과 측정 자세는 바꾸지 않는다. X-ray 보기에서는 지그·팔만 투명화해 가려진 고리의 위치를 확인한다.

원본의 용접 그룹/부모 관계/명시적 제외에서 가져온 로봇 내부 충돌 필터 122쌍을 적용한다. 나머지 자기 충돌과 양팔 충돌은 켠다. 중력 보상 로봇은 원본과 같이 중력 보상을 사용하고 부품은 중력 9.81m/s²를 받는다. 핀은 원본의 가상 TCP 대신 실제 양쪽 패드 안쪽 면의 평균점을 기준으로 잡는다. 패드 로컬 접촉점 `[0, -6.6, 35]mm`을 부품 로컬 `[0, -0.25, -15]mm` 밴드에 맞춘다. 원본 자세에서 계산한 손 기준 이동 보정은 약 `[-6.98, 0.22, -1.07]mm`이며, 접근·운반·해제 구간에 부드럽게 적용한다. 잡기 전 팔의 실제 위치·속도가 안정됐는지 확인하고, 양쪽 패드에서 각각 5N 초과 접촉이 3회 연속 확인된 뒤 들어 올린다. 핀 드라이버에는 힘을 확보하기 위한 0.01rad 닫힘 목표 여유를 주되 구동력 한도 5Nm를 유지한다. 파지·접근에는 측정된 물체 자세 피드백을 사용한다. 삽입 보호는 접촉 충격량 벡터를 합한 합력으로 계산하며, 크기의 합을 실제 합력으로 간주하지 않는다. 링 20N·핀 50N을 제어상의 보호 기준으로 가정한다. 핀이 최종 위치·자세에 도달하면 착좌 단계로 처리해 불필요한 후퇴/대기를 피한다. 이 값은 실물 힘 한도의 인증이 아니다.

힘 데이터는 [PhysX 접촉점 API](https://nvidia-omniverse.github.io/PhysX/physx/5.1.0/_build/physx/latest/struct_px_contact_pair_point.html)의 월드 좌표 충격량을 물리 시간 간격으로 나눈다. 접촉점 크기의 합과 부품 기준 방향을 맞춰 더한 합력 벡터를 모두 보존한다.

CPU PhysX TGS 480Hz, 자세·접촉 피드백 120Hz, 팔·능동 그리퍼 명령 480Hz, 전체 바디 상태 30Hz, 버튼 스트로크 480Hz를 사용한다. 실제 1.8mm 누름이 최소 100ms 연속 확인된 뒤 오른팔 목표를 고정한다. 순간적인 접촉 피크에는 완료를 선언하지 않는다.

## 성공 조건

각 부품에서 다음을 모두 만족해야 한다.

- 운반 중 양쪽 패드의 실제 접촉 비율 80% 초과, 초기 위치보다 15mm 이상 상승.
- 삽입 후 양측 클램프 접촉 확인 및 로봇 손 해제.
- 해제 0.5초 뒤부터 최소 1초 이상 위치 오차 0.8mm 미만, 축/자세 오차 0.04rad 미만, 속도 5mm/s 미만 유지.
- 최종 로봇 손 접촉 해제 및 2개 이상 클램프 죠의 접촉력 0.5N 초과.

원형 링의 축 방향 회전은 판정에서 제외한다. 버튼은 세 부품 해제 뒤 실제 접촉으로 1.8mm 이상 눌린 상태가 100ms 이상 유지되어야 한다. 의도하지 않은 로봇-설비/클램프 또는 양팔 충돌력은 20N 이하여야 한다. 표준 자연 sleep을 허용하며 임의로 정지시키거나 속도를 덮어쓰지 않는다. 활성 상태에서는 실제 접촉 충격량을 힘으로 환산한다. 잠든 물리 island는 새 충격량을 보고하지 않으므로 collider 쌍의 FOUND/PERSIST/LOST 수명을 추적한다. 최종 접촉은 새 힘 측정 또는 실제 `is_sleeping`인 부품·죠의 유지된 접촉 쌍과 이전 preload 측정으로 확인한다. LOST 이벤트는 해당 쌍을 즉시 제거한다. 과거 힘을 현재 측정 힘으로 표시하지 않는다. `trace.json`의 `sleeping`, `active_clamp_contacts`, `last_force_time_s`를 함께 감사한다. 속도·위치 한도는 그대로 적용한다.

`--only-pin`, `--partial-env`, 중간 시각에서 시작한 진단은 전체 작업 성공으로 판정하지 않는다. `hardware_assembly_certified`와 `source_cad_nominal_fit_certified`는 계속 `false`다.

## 실행과 결과 확인

서버에 준비된 입력을 사용한다.

```bash
/home/gpuadmin/workspace/jake/mujoco/isaac_port/run_contact.sh
isaac status
```

공용 실행 도구가 빈 GPU를 예약하고 동역학 → 독립 판정 → 측정 상태 렌더링 후 해제한다. 필요한 개인 작업공간 패키지는 `mujoco==3.11.0`, `scipy==1.18.1`, `ruckig==0.12.2`다. 공유 이미지를 수정하지 않는다. 정밀 접촉 시험은 실시간보다 느리다.

입력을 재생성하려면 복원된 호스트 `.venv`에서 `prepare.py --scene cap_button`, `prepare_contact.py`, `export_precision_cad.py`, `export_precision_cad.py --pin-main`, `prepare_robot_filters.py`, `audit_cad_interference.py`, `audit_pin_brep.py`, `prepare_contact_timing.py --fast`, `plan_right_posture.py --fast`, `prepare_fr3_posture.py`를 실행한다. 현재 FR3 자세 생성기는 보존된 `runs/contact-fast-30` 기준 입력을 사용한다. 호스트의 MuJoCo/SciPy/python-fcl/OCP가 필요하다. USD는 공용 Isaac 환경의 `convert.py --scene cap_button`으로 준비한다.

각 실행 디렉터리에서 확인한다.

- `run-manifest.json`, `implementation/`: 실제 실행 인자, 입력/코드 SHA-256, 코드 사본. 계획한 관절 기준과 `recording/`의 전체 기준 입력도 실행별 보존한다. 실행 중에는 로컬 제어 모듈을 이 코드 사본에서 불러와 후속 편집의 영향을 막는다.
- `dynamics-audit.json`: 엔진, 질량·중력, 부품 연결 관절 부재 및 진단 범위.
- `scene.usda`, `configuration.usda`: 원본 참조와 해당 실행의 물리/시험 배치 설정.
- `trace.json`, `contacts.json`, `clamp-events.json`: 측정 상태·접촉력·개폐 이벤트.
- `physics-tape.npz`, `tape-bodies.json`, `body-paths.json`: 측정된 모든 바디/관절의 영상 입력.
- `acceptance.json`: 부품별 파지·해제 후 유지·최종 접촉과 버튼 판정.
- `render/m80-physx-contact.mp4`, `render/contact-sheet.png`: 실제 시간으로 재생하는 공정 구간. 불투명 전체 장면과 X-ray 확대 화면을 합성한다. 두 렌더의 입력 테이프·시각·프레임 수가 같은지 검사한다. 초기 안정화·최종 유지 검증을 포함한 전체 상태는 테이프에 남긴다.

실패한 연구 실행도 `runs/`에 보존한다. PhysX의 정밀 SDF 보고에서 `getMaterialFromInternalFaceIndex` 경고가 반복될 수 있어 로그를 보존한다. 경고를 통과 판정으로 바꾸지 않는다. 기존 기록 재생/관절 smoke test와 이번 물리 작업의 판정은 분리한다.
