# 저장 경로 + RGB-D 보정: 446 전체 성공

고정 공급 배치에서 **작은 링 전달·왼손 삽입 중 오른손 큰 링 파지·상승 → 큰 링 삽입 → 핀 단일 축 삽입 → 손 철수·고정 유지**를 실제 Isaac Sim/PhysX 접촉으로 완료했습니다. 부품 부착과 초기화 후 물체 위치 변경은 없습니다. 입력은 RGB-D 영상과 공개 로봇·그리퍼 엔코더이며, 물체의 내부 상태는 평가·영상 재생에만 사용합니다.

첫 촬영부터 마지막 유지 확인까지 **249.18초**, 진행한 물리 시간은 **47.92초**입니다. 모든 촬영·인식·계산·동작 대기를 포함합니다. 이전 432 성공의 관측 시간은 302.66초였지만 동시 실행 부하가 달라 통제된 성능 비교는 아닙니다. 20/30초와 실제 로봇 전체 실행은 미달성입니다.

## 실행 구조

1. **작업 시작 전:** 저장된 로봇 명령, CAD·로봇 모델·고정 설비·클램프 스트로크·보정값의 지문을 확인합니다. 일치하는 증명 파일이 있으면 불러오고, 없으면 원래 PhysX 검사로 생성합니다.
2. **실행 시:** RGB-D로 링의 크기·중심·방향·앞뒤를 검출하고 집기 접근을 계산합니다. 집기 후 다시 촬영해 실제 손과 물체의 관계를 구합니다.
3. **경로 연결:** 달라진 집기/진입 구간은 원래 충돌 검사로 확인한 뒤 저장 운반 경로에 연결합니다. 작은 링 왼손 운반 720개, 큰 링 오른손 운반 1415개 명령을 저장 경로로 사용합니다.
4. **재사용 범위:** 증명된 고정 설비 검사만 재사용합니다. 현재 반대 팔, 실제 파지 변화, 이미 삽입된 부품, 손가락 폭, 접촉 및 FR3 한도는 실행 당시 상태로 확인합니다. 환경·보정·모델이 달라지거나 파지가 증명 범위를 벗어나면 원래 검사/계획으로 돌아갑니다.
5. **삽입:** 새 RGB-D 관측으로 오차를 계산·보정하고 삽입·고정 후 손을 뺀 상태를 확인합니다. 중간 LLM/agent 판단 없이 정해진 함수와 조건 분기로 동작합니다.

큰 링 고정 설비 검사 **7085건 재사용 / 새 시작점 5건 검사**, 작은 링 왼손 **3605건 재사용**를 실제 기록에서 확인했습니다. 물리가 진행되지 않은 동일 상태에서 중복되던 작은 링 792개 명령의 검증도 한 번만 수행했습니다. GPU 양팔 검사는 원래 형상·여유값을 유지하면서 변환 행렬의 중복 전송을 줄였습니다. 별도 같은 입력 비교에서 7075개 상태가 모두 CLEAR로 동일했고 클라이언트 시간은 약 12.0초→1.61초였습니다. 전체 작업 시간과 구간 비교 시간을 혼동하지 마세요.

최초 고정 경로 증명 생성은 오른손 64.01초 + 왼손 47.27초가 들었으며 첫 촬영 전에 수행했습니다. 이 준비 시간은 249.18초에 포함되지 않습니다. 증명 파일은 `precompiled-static-proofs/`에 보존했지만 다른 장면·로봇·보정에 그대로 적용할 수 없습니다.

## 실제 시험 결과와 범위

`acceptance-summary.json`에 결과와 명령 한도 검사를 요약했습니다. 전체 발행 명령 23003개에 대해 기존 95% 위치별 속도 한도, 가속도 9.5 rad/s², jerk 4750 rad/s³를 유지했습니다. 관측된 실제 엔코더 속도의 최대값은 95% 속도 상한의 약 92.9%였습니다. 파지력·질량·마찰을 높여 통과시키지 않았습니다.

이 성공은 원래 고정 배치 1회입니다. 위치를 바꾼 시험은 별도 결과로 기록해야 합니다. `±10mm` 입력은 허용 범위의 성공 보장이 아닙니다. 447의 반대 방향 변경 시험에서는 선반과 손끝의 충돌 때문에 큰 링 집기 전에 정지했으며, 이 실패를 전체 성공으로 계산하지 않습니다.

현장과 다른 알려진 모델 조건도 남아 있습니다. 핀 홀더는 사진 기반 대리 형상이며 실측 전이고, 핀 충돌 형상에는 축 지름 0.2mm 반경 여유 및 CAD의 미세 홈 생략이 있습니다. 클램프 중심·마찰·카메라 보정·실제 로봇 연결은 검증 전입니다. 이 연구 체크포인트가 현장 전속 실행을 승인하는 의미는 아닙니다.

## 파일과 사용

- `code/`: 실제 실행한 Python과 정적 입력의 바이트 복사. `code-manifest.json`과 `exact-code-manifest.json`으로 확인합니다.
- `trial-config.json`: 실제 설정. `fixed_prevalidated_routes`, `fixed_saved_route_priors`, GPU 서비스 경로를 확인합니다.
- `precompiled-static-proofs/`: 위 장면에서 생성한 증명. 로더가 모델·장면·파지 범위 지문을 확인합니다.
- `service-sources/`: 실행에 사용한 GPU 양팔 검사와 RGB-D 서비스 소스. 서비스의 socket 경로와 CUDA 환경은 서버 설정 항목입니다.
- `pipeline-results.json`, `executed-actuator-commands.npz`, `physx-sequence-trace.npz`: 원본 결과·발행 명령·평가용 물리 기록.
- `camera-example/`: 실제 첫 RGB-D 촬영 예시. 내부 물체 기록을 인식 입력으로 대체하지 않습니다.

전체 CAD, 원래 `native-roas-table-bin-retimed14` 장면, Isaac Sim, 기존 `bin-picking` 의존 파일, GPU 경로 서비스가 필요합니다. 이 폴더는 독립 설치본이나 libfranka 실행기가 아닙니다. 서버에서는 이 정확한 소스를 별도 frozen 작업 디렉터리로 적용해 실행하며, 기존 실행 중 소스를 덮어쓰지 않습니다.

실제 RealSense 입력 도구는 [고정 배치 카메라 어댑터](../../../fixed_front_rgbd_adapter_20261022/README.md), 로봇·그리퍼·PLC 설정과 저속 시운전은 [현장 안내](../../../FIELD_RGBD_20261022.md)를 사용합니다. 최신 저장 경로/동시 정책의 SDK 전체 실행은 별도 통합·실기 확인이 필요합니다.
