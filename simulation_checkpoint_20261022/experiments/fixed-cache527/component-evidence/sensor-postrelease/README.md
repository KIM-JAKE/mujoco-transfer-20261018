# Fresh public RGB-D postrelease retention, default off

This exact522-based patch adds `pin_postrelease_rgbd_retention`. Add that flag to the driver config allowlist, then enable it alongside the existing fixed-mode qualified full-depth, robust cap and near-axis-view policies. Nondeferred PIN-last/component execution is required so the existing0.5s physical retention wait remains intact. A deferred recipe needs its own final sensor check rather than silently claiming this contract. No motion, grasp force/speed, insertion precision or shared16-image budget is changed.

Old522 completed clamp/release/withdraw, waited0.5s and read `truth['pin'].get_transforms()` to set its PIN pass/fail. It never captured a postrelease RGB-D image. Under the new flag, the last qualified pre-release public PIN world center/axis is retained only as a camera aim/ROI prior. It is re-expressed relative to EACH current SDK Hand immediately before requesting a frame, so45mm robot withdrawal cannot move the camera's world anchor. Camera placement and every pose fit remain pixel/SDK only; no body-pose seed is introduced.

After the unchanged retention wait, public SDK checks require release target9mm per finger within0.5mm measured tolerance and completion of the already checked withdrawal within1.5mm/50mrad. No extra correction/movement is allowed. Exactly one fresh observation operation follows, using the existing two near-axis candidates followed by all13 original fallback views. Each capture retains the original3s deadline, known class radius,240degree robust arc,12edge inliers/75percent support and60µm circle RMS. Copied/propagated XY cannot pass. The capture must occur after release, withdrawal and the retention wait. Fresh measured center/axis must satisfy the unchanged full-depth1.5mm/50mrad limits. Any failure raises and blocks PIN completion. This final check is separate from the16 insertion images.

When enabled, `pin_single_stroke_pass` and its final errors come only from the new public RGB-D/SDK check. Simulator truth, if available, is stored separately under `pin_retention_EVALUATION_ONLY` and cannot change that decision; unavailable truth is harmless. The outer experiment/global final-check driver may still have separate evaluator gating and must be reviewed by root. With the new flag disabled, the original legacy completion branch remains unchanged.

Focused CPU tests cover original522 release/withdraw SDK values, direct cap/pose limits, rejected propagated/stale images, a world anchor unchanged across moving SDK frames and fallback captures, one observation operation, unavailable truth having no influence on the measured verdict, and all other nested motion/servo functions remaining unchanged. No GPU/physics trial was run. Source522 SDK endpoint errors were0.286mm/.859mrad with actual fingers8.99834mm each.

No live/shared direct_pin_skill, worker, source snapshot or runtime state was modified. Root merges this narrow diff with the independent optional-depth-correction patch and owns subsequent physical validation.
