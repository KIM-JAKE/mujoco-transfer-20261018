# 467: MINUS 위치 변경, articulation sleep 설정 진단

원래461 MINUS 코드에 로봇 articulation sleepThreshold=0만 적용한 진단 실행입니다. 링2개·핀1개는 완료했지만, 정밀 보정 중 실제 관절 위치가 멈추고 속도 신호는 남는 시뮬레이터 현상이 계속 관측됐습니다. 이 설정이 원인을 해결했다거나 속도 개선의 원인이라는 주장은 하지 않습니다. 이후 확인한 [NVIDIA TGS 설명](https://forums.developer.nvidia.com/t/dof-velocity-offset-at-rest/205799/13)에 따르면 프레임 간 관절 위치 변화와 마지막 내부 단계의 속도 신호는 다를 수 있습니다. 따라서 이 관측만으로 엔진 고장·정지 실패를 진단하지 않습니다. 원래 위치 기반 정지 확인과 기본 모델을 유지하며, 엄격한 순간 속도=0 조건으로 바꾸지 않습니다.

- 실제 Isaac Sim/PhysX 전체 작업 성공: `True`, RGB-D 파이프라인 성공: `True`.
- 첫 촬영부터 최종 유지 확인까지 **228.66초**, 물리 시뮬레이션 **45.96초**. 20/30초 목표는 달성하지 못했습니다.
- 첫 촬영 전 준비 **330.15초**. 이 시간은 위 작업 시간에서 제외되어 있으며, 냉간 시작 총시간을 작업 시간과 혼동하면 안 됩니다.
- 여러 작업을 병렬 실행했으므로 다른 실행과의 시간 차이를 독립적인 성능 측정으로 해석하지 않습니다.
- FR3/Hand 제한과 원래 충돌 기준 유지. 부품 부착·초기화 후 순간이동 없음. 실기 로봇 검증 없음.
- 정확한 소스·입력 `412`개: `exact-source-manifest.json`, `SOURCE_SHA256SUMS`. 원본 결과·명령·카메라 관측·물리 기록을 함께 보존했습니다.

[실제 기록 영상](../../media/fixed-cache467-awake-minus-all3-pass-excerpts-1x.mp4)은 실제 벽시계 기준 1배속 발췌입니다. 긴 대기는 CUT 카드로 표시하며 원래 전체 시간이 계속 표시됩니다. 렌더를 위해 기록된 장면 자세를 재생할 뿐, 제어에 실제 물체 좌표를 공급하지 않습니다.

[서버 재실행 안내](../../FIXED_CACHE_RUN.md)의 checkpoint 경로를 이 디렉터리로 바꾸세요. 전체 복원 CAD·생성 장면과 현재 GPU 서비스가 필요합니다. 현장 SDK 실행 준비와는 별개의 시뮬레이션 결과입니다. 모델·실물 차이와 아직 검증하지 않은 조건은 [공통 안내](../../../FIXED_FRONT_20261022.md)를 참고하세요.
