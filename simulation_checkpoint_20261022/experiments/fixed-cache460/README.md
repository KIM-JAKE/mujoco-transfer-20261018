# 저장 경로 + RGB-D 보정: 기준 위치460 전체 성공

기존 M80 선반의 **핀 → 작은 링 → 큰 링** 배치에서 실제 PhysX 파지·전달·세 부품 삽입·고정 유지·손 철수를 완료했습니다. 작은 링 왼손 운반/삽입 중 오른손이 다음 큰 링을 실제로 집고 들어 올립니다. 부품 부착과 초기화 후 물체 이동은 없습니다.

**촬영·인식·검사·동작·유지 확인 전체234.93초 / 물리45.31초.** 이전432의 관측 시간302.66초보다 짧지만 실행 부하/정책이 달라 통제된 비교는 아닙니다. 20/30초와 실기 전체 주기는 미검증입니다. [실제1배속 영상: 긴 대기CUT·원래 전체 시간 표시](../../media/fixed-cache460-nominal-all3-pass-excerpts-1x.mp4).

## 실제 재사용

- 작은 링 왼손720개 저장 명령 + 새 진입 구간. 고정 설비 검사3605건씩 두 번, 자기충돌 검사7215건 재사용.
- 큰 링 오른손1415개 저장 명령. 고정 설비·자기충돌·보유 부품과 자기 팔 검사 각각7085건 재사용. 새 시작점5건과 변경된 진입은 원래 검사 유지.
- 상대 팔/손가락 폭, 이미 삽입된 부품, 현재 RGB-D 파지, 실제 엔코더, 접촉과 FR3 명령 한도는 계속 확인.
- 저장 증명 로딩: 오른손 두 파지 영역3.885초 + 왼손1.794초, 합계5.679초. 첫 촬영 전 준비이며 전체234.93초와 별도. 최초 생성 시에는 더 오래 걸립니다.

이 코드는 카메라가 다르게 표현한 링 방향을 임의로 정규화하지 않습니다. 서로 다른 두 파지 좌표계의 원래 CAD를 각각 사전 검증하고 현재 관측이 들어가는 영역만 선택합니다. 새로운 편심 파지 영역은 후속461/462에서 따로 시험하며 이460 성공에 섞지 않습니다.

PIN 보정은 원래75µm 중심/3mrad 축/150µm 전체 축 오차 기준 그대로 두 번 수정해 통과했습니다. 적응 이득 옵션이 켜져 있지만 이번에는 두 번 모두 개선돼 이득1을 유지했습니다. 작은 링 일회 재확인 분기도 호출되지 않았습니다. **해당 두 fallback 분기는 이 성공만으로 물리 검증됐다고 주장하지 않습니다.**

`SOURCE_SHA256SUMS`로 실제 소스411개를 확인할 수 있습니다. `support-code/`는 원래 frozen 상위 모듈, `code/`는 실행한 native 모듈과 정적 입력입니다. `acceptance-summary.json`은 원본 결과/명령 한도/캐시 기록 요약입니다. 기록된 내부 물체 좌표는 렌더링/평가용이며 제어 입력이 아닙니다.

[서버에서 정확한 소스 준비/재실행](../../FIXED_CACHE_RUN.md). 전체 생성 CAD 장면·Isaac·기존 의존 파일·GPU 서비스가 필요합니다. libfranka 실행기가 아니며 실제 카메라·로봇·PLC 연결은 별도 [현장 안내](../../../FIELD_RGBD_20261022.md)를 따릅니다. 핀 충돌 형상 여유, 사진 기반 홀더, 센서 광축 해석 등 [기준446의 실물 차이](../fixed-cache446-pass/README.md)는 그대로 적용됩니다.
