This repeats the historical accepted layout with the newer actual-opposite-arm checks; it does not establish new-layout reliability,20/30seconds or hardware operation. Parallel trials make this unsuitable for a causal timing comparison.

Unpreviewed checks now bind the actual opposite-arm encoders. Serial carry, preposition and receiver approach validate actual starting state, commanded state and every retimed issued row across both Hands' width contexts before motion. RIGHT annular GPU proposals apply only to carried rings; PIN and empty transport retain their original backend. All original force, velocity, acceleration, jerk, self/fixed/payload/placed-part and final acceptance gates remain. No workpiece attachment or post-initialization teleport occurs.

The239 source/static inputs in `code-manifest.json` are copied byte-for-byte and hash-verified. Server CAD, generated query meshes, earlier class/robot priors and Isaac runtime remain external: this is an exact research checkpoint, not a standalone scene. The separate field package still has admission blockers and no full real-robot validation.

The final aggregate is the report's top-level `full_task_pass` and `vision_end_to_end_pass`. Source actor traces are evaluation/replay data only; the controller consumes simulated RGB-D and robot encoders. CPU planning pauses physics while its waits count in wall time, so67.67physics seconds is not a hardware cycle-time prediction. Virtual camera banks and the7.6mm collision shaft versus nominal8mm PIN remain SIM assumptions.
