# 높인 배치의 독립 cuRobo 모델 검증

이 폴더는 575 성공본을 읽어 만든 별도 검증 자료다. 기존 성공본, 실행 중인 시험, GPU 서비스, 공유 모델을 수정하지 않는다. 실제 로봇에 연결하거나 명령을 전송하는 기능은 없다.

## 완료된 CPU 준비

- 575의 입력 11개를 해시 확인 후 별도 복사하고 읽기 전용으로 보존했다. `input-manifest.json`에 원본 경로와 SHA-256이 있다.
- 높인 USD 관절 모델에서 독립 URDF를 만들었다. 실제 기록 256개 자세와 비교한 TCP 위치 오차는 최대 약 0.61 µm, 회전 오차는 약 1.33 µrad였다. URDF 변환 후 FK 차이도 검사했다.
- 활성 충돌 CAD에서 내보낸 정적 삼각형 8,808,780개를 축소 없이 준비했다. 새 기둥과 받침판은 USD에서 정확한 별도 cuboid로도 추출했다.
- 팔, Hand, 양쪽 손가락, 핀의 볼록 껍질 전체를 덮는 보수적인 구 모델을 만들었다. 각 CAD의 모든 정점과 무작위 삼각형 내부 표본을 검사했고 덮이지 않은 표본은 없었다. 구 모델은 실제 형상보다 크게 잡히므로 가능한 경로를 막을 수 있다. 정밀 충돌 검사와 속도 비교가 남아 있다.
- 기둥·받침판의 면 주변에 구형 탐침 84개를 만들었다. 해석적으로 충돌하는 점을 voxel 모델이 놓치는지 비교할 입력이다.
- 실제 기록의 핀 들어 올림·운반·삽입 관절 자세를 진단용으로 추출했다. 제어 목표에 privileged 물체 위치를 쓰거나 물체를 고정하는 기능은 없다.

`cpu-readiness.json`이 측정 결과이며, `prepared/`에 모델과 시험 입력이 있다.

## GPU 1에서 완료한 독립 비교

물리 시뮬레이션을 돌리지 않고 cuRobo의 실제 충돌 API와 FCL 기하 검사를 대조했다. GPU 1의 이전 용량 시험이 종료된 것을 확인한 뒤 실행했다. 공유 서비스나 다른 GPU는 사용하지 않았다.

| 측정 | 8 mm voxel | 4 mm voxel |
| --- | ---: | ---: |
| 정적 지도 전체 재생성, 준비 후 중앙값 | 0.329 s | 2.129 s |
| 기둥·받침판의 명확한 충돌 탐침 누락 | 0 / 48 | 0 / 48 |
| Hand·손가락·핀 형상 비교 조건 | 66 | 66 |
| FCL에서 충돌한 조건을 놓친 수 | 0 / 6 | 0 / 6 |
| FCL에서 통과한 조건을 추가 차단 | 3 / 60 | 3 / 60 |
| 준비 후 단일 자세 충돌 질의 중앙값 | 0.622 ms | 0.410 ms |

각 GPU 질의 시간은 동일 입력을 6회 검사한 뒤 첫 회를 제외한 중앙값이다. 커널 컴파일, 모델 준비, 관절 FK, 데이터 전송, 환경 갱신, 경로 생성은 포함하지 않는다. 66개 조건을 한 번에 검사한 시간도 별도로 저장했다. 위 수치는 GPU 스케줄링·CPU 호출 비용의 영향을 받는 소규모 측정이며, 4 mm가 8 mm보다 빠르다는 순위 근거로 쓰면 안 된다.

FCL 참조는 원래 추출기를 이용해 비부착 USD에서 활성 충돌 형상 2,795개를 읽었고 누락된 지원 불가 형상은 없었다. 처음 준비하는 데 약 42.45초가 걸렸으며, 이 시험의 Hand/핀 형상 1건 충돌 질의 중앙값은 약 0.053 ms였다. 이 결과만으로 GPU가 단일 질의에서 CPU보다 빠르다고 볼 수 없다. 반복 실행 시 CAD를 매번 처음부터 읽는 것과, 준비된 모델에서 현재 상태만 갱신하는 것은 시간을 분리해서 평가해야 한다. 현장의 실제 대기 원인은 현장 로그를 확인해야 한다.

과잉 차단 3건은 `trace5446`의 기본 위치 및 X ±10 mm 형상 탐침이다. 모두 손바닥 커버 구에서 발생했다. 해당 구를 voxel을 거치지 않고 원본 삼각형에 직접 대조해도 약 1.45~5.37 mm의 겹침이 나왔다. 손바닥 볼록 형상 자체는 FCL에서 통과하므로, 이번 보수적인 셀 커버가 바깥으로 부푼 것이 이 반례의 원인이다. voxel 해상도를 높이는 것만으로 해결되지 않았다. **이것은 새 비교용 모델의 반례이며, 기존 운영 모델이나 핀 시험의 실패 원인을 확정한 결과가 아니다.**

세부 결과는 `fcl-readiness.json`, `hand-case-manifest.json`, `gpu-results/voxel-8mm/`, `gpu-results/voxel-4mm/`에 있다. 과잉 차단의 구 중심·반경·직접 CAD 거리도 각 `curobo-hand-comparison.json`에 보존했다.

## 중요한 한계

575는 시뮬 전체 성공 1회다. 이 성공에서 삽입 전 비전 정렬 기록은 11개 iteration이다. 마지막 보정 자세를 저장하는 것만으로 같은 파지에서 비전 보정 없이 성공한다고 입증할 수 없다. `pin-reference-anchors.json`은 후보 자세와 실제 보정 후 자세를 구분한다.

현재 결과는 다음을 입증하지 않는다.

- cuRobo 경로의 정밀 충돌 통과, 경로 생성 속도 또는 3부품 반복 성공률
- 같은 파지로 운반한 뒤 보정 없이 고정 경로를 삽입하는 동작
- 실제 하드웨어나 실제 카메라에서의 성능

GPU 구 모델의 볼록 껍질 커버는 전체 약 2만 개의 구를 사용한다. 정밀도 비교용 기준 모델이며, 빠른 실행에 적합한 구 개수는 아직 평가하지 않았다. 셀 크기/근사 방법을 바꿀 때마다 누락과 과잉 차단을 다시 측정해야 한다.

## 실행

CPU 준비와 원본 보존 확인:

```bash
env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  /tmp/m80-nlp-plan-venv/bin/python /home/gpuadmin/workspace/jake/curobo-raised-qualification-20261023/prepare.py
env PYTHONDONTWRITEBYTECODE=1 \
  /tmp/cell-layout-audit-20261022/bin/python /home/gpuadmin/workspace/jake/curobo-raised-qualification-20261023/extract_mount.py
/tmp/m80-nlp-plan-venv/bin/python /home/gpuadmin/workspace/jake/curobo-raised-qualification-20261023/prepare.py --verify-only
```

`build_esdf_gpu.py`는 준비된 CAD로 GPU voxel 모델을 만들고, 알려진 기둥·받침판 충돌 누락을 측정하는 독립 시험이다. `check_curobo_gpu.py`는 실제 cuRobo 충돌 API를 이용한 형상 비교다. 두 스크립트 모두 GPU 1에서 실행했다. 결과와 GPU 캐시는 이 폴더에만 쓴다. 공유 cuRobo 서비스를 호출하지 않는다.

FCL 참조 데이터 재생성은 컨테이너에서 기존 `bin-picking/realtime-deps-python312`를 PYTHONPATH에 추가한 뒤 `fcl_oracle.py --hand-cases`를 실행한다. GPU 비교는 할당받은 Isaac 컨테이너 안에서 다음과 같이 재현한다.

```bash
bash /workspace/project/curobo-raised-qualification-20261023/run_gpu_comparison.sh
```

남은 경로 검증 작업은 다음과 같다.

1. 위 반례를 유지한 채 손바닥 커버의 과잉 차단을 줄이고 다시 대조한다. 얇은 받침판은 별도 cuboid로 유지한다.
2. 동일한 Hand 개구 폭, 측정 파지 관계, 다른 팔 자세, 설치된 링·지그 상태를 포함해 정밀 충돌 검사와 대조한다.
3. 허용된 모델에서 검증된 삽입 직전 **관절 자세**까지 경로를 만든다. 준비·컴파일·워밍업·경로 생성·정밀 검증 시간을 각각 기록한다.
4. 운반 후 핀 파지가 유지된 경우에만 원래 힘·속도 제한을 유지한 고정 삽입을 연결한다. 파지·운반 안정화는 저쪽 시험 담당이며, 보정 없는 성공을 별도로 측정한다.

현재 비교는 기록된 형상을 이용한 **Hand·손가락·핀 대 정적 CAD** 시험이다. 정밀 참조는 각 이동체 전체의 볼록 껍질이며, 그리퍼 내부 접촉을 검사하지 않는다. 다른 팔, 설치된 링, 현재 클램프 상태, 로봇 자체 충돌을 포함한 경로 검증은 남아 있다. 일부 조건은 의도적인 충돌 형상 탐침이므로 실제로 실행할 수 있는 관절 경로가 아니다.

GPU 비교 프로세스는 모두 종료했다. 이전 용량 시험은 이 작업에서 중단하지 않았다. 기존 성공본과 원본 입력 11개는 작업 후 SHA-256으로 다시 확인했다.
